# 秋海风格写作 Skill 使用说明

## 这是什么

`qiuhai-writer` 是一个面向中文长文写作的风格化写作 skill。  
它适合处理公众号文章、第一人称随笔、生活观察、跑步主题、家庭 / 育儿反思、个人经验复盘等任务。

它的目标不是“把文章写得像公众号”，也不是单纯模仿表面语气，而是稳定复现这样一种写法：

**从具体事件进入，呈现真实反应，辨认自身动机，完成一次克制、诚实、带留白的自我拆解。**

一句话概括：

> 用平实克制的第一人称叙述，把外部事件写成一次内心辨认。

---

## 为什么要单独做这个 skill

普通写作 prompt 往往只能控制：
- 口吻
- 字数
- 结构
- 是否像“成熟公众号”

但“秋海风格”真正难模仿的，不是词句，而是下面这些更深层的东西：

- 从哪里切入
- 怎么从事件走到内心
- 怎么承认自己的不体面
- 怎么完成一次自我纠偏
- 怎么避免写成说教、鸡汤、模板文
- 怎么减少 AI 味，保留“活人感”

所以这个 skill 不是一个简单的“风格提示词”，而是一套完整的：
- 写作原则
- 结构方法
- 反向约束
- AI 协作边界
- 四层自检体系

---

## 什么时候应该调用

适合调用这个 skill 的场景：

- 用户要写公众号长文
- 用户要把素材整理成成熟成稿
- 用户要按自己的风格改写文章
- 用户要把经历、语音转录、聊天记录整理成文章
- 用户明确提到：
  - 用我的风格写
  - 模仿秋海风格
  - 写成公众号文章
  - 帮我把这件事写成文章
  - 帮我整理成一篇完整文章
  - 按这个语料的感觉来写

---

## 什么时候不应该调用

以下场景不建议调用：

- 纯资讯整理
- 新闻播报
- 商品带货文案
- 小红书短帖 / 推文 / 朋友圈短文
- 强口播感、强反转、强情绪刺激内容
- 纯知识科普，不带个人经验与内心辨认的写作

如果任务本身不需要第一人称、不需要生活感、不需要“我”的内心推进，这个 skill 往往不是最佳选择。

---

## 这个 skill 和普通写作 skill 的区别

它和一般“长文写作 skill”最大的不同，不在于文风，而在于写作重心：

### 普通写作 skill 更关注
- 信息是否完整
- 结构是否清晰
- 观点是否成立
- 表达是否顺滑

### 秋海风格 skill 更关注
- 是否从具体生活切口进入
- 是否写出了真实反应
- 是否保留了不体面的部分
- 是否出现了自我纠偏
- 是否避免了说教与模板味
- 是否有“真实的人在梳理自己”的感觉

换句话说，普通 skill 更像“把内容写清楚”，这个 skill 更像“把人写出来”。

## 推荐使用方式

### 用法一：用户给完整原文，要求风格改写
适合：
- 改写旧稿
- 去 AI 味
- 调整成更接近秋海风格的版本

推荐做法：
1. 先提炼原文核心主题
2. 判断原文真正的底层问题
3. 重建叙述线，不照搬原结构
4. 强制加入“先承认，再纠偏”的动作
5. 终稿跑四层自检

---

### 用法二：用户给零散素材，要求整理成文
适合：
- 语音转文字
- 素材卡片
- 零散经历
- 半成品草稿

推荐做法：
1. 先提炼表层主题
2. 再提炼底层主题
3. 只保留一个唯一落点
4. 采用“事件—情绪—拆解—回收”结构
5. 不要把所有素材都塞进去

---

### 用法三：用户只给一个主题
适合：
- 命题写作
- 想法雏形
- 还没有完整素材的情况

推荐做法：
1. 先找最自然的生活切口
2. 优先使用常见、可信、生活化的细节
3. 不要为了深度硬编戏剧性情节
4. 保持真实感优先于“好看”

---

## 推荐工作流

这个部分也吸收了成熟写作 skill 常见的做法：先判断选题和素材，再明确 AI 的角色边界，再进入写作和质检流程。参考 skill 明确强调 AI 更适合做结构、归纳、扩写和质检，而不适合伪造第一手观察与真实情绪；同时强调“讲人话，像个活人”“真诚是唯一的捷径”。这些思路很适合用来约束秋海风格写作。 citeturn546034view0

推荐流程如下：

1. **识别任务类型**
   - 原文改写
   - 素材整理
   - 主题命题
   - 风格校正

2. **提炼双层主题**
   - 表层主题：事情表面在写什么
   - 底层主题：这件事真正牵动“我”的是什么

3. **确定唯一落点**
   - 一篇文章只保留一个核心落点

4. **选结构**
   - 事件—情绪—拆解—回收
   - 现象—误判—纠偏—落地
   - 小事切入—扩展到关系 / 自我—再落回小事

5. **扩写**
   - 保留具体场景
   - 保留真实反应
   - 至少加入一次自我纠偏

6. **四层自检**
   - L1 硬性规则检查
   - L2 风格一致性检查
   - L3 内容质量检查
   - L4 活人感终审

## AI 与用户的协作边界

这个 skill 默认遵守以下协作原则：

### 更适合交给 AI 的
- 提炼主题
- 归纳结构
- 找重复和悬空表达
- 风格校正
- 扩写已有角度
- 做质检和去 AI 味检查

### 必须尽量留给用户真实素材的
- 第一手经历
- 真实情绪节点
- 明显带个人体感的细节
- 只有本人会有的反应
- 明显属于作者自身观察得来的角度

原则很简单：

> **AI 负责梳理、组织、扩写、质检；真实经历、真实体感、真实犹豫，优先来自用户。**

---

## 如何判断这次调用是否成功

一次成功的调用，通常满足下面这些条件：

- 开头不是大道理，而是一个具体生活切口
- 文章里有真实情绪，不只是观点
- “我”不是永远正确的
- 至少有一次“先承认，再纠偏”
- 抽象词都落到了细节上
- 结尾没有喊口号
- 通读时像真实的人在说自己，而不是稳定输出的系统

如果一篇文章写完后：
- 全是正确观点
- 没有真实犹豫
- 没有具体场景
- 句句都像模板金句
- 结尾像演讲总结

那基本说明这次 skill 调用没有真正成功。

## 建议在 README 中如何引用文件

如果项目里保留三份文件，可以这样组织：

- `SKILL-final.md`：项目主版本，推荐默认使用
- `SKILL.md`：较完整说明版，便于人工阅读和继续编辑
- `SKILL-compact.md`：更短、更适合模型直接读取的压缩版

推荐默认引用：

```md
主 skill 文件：`SKILL-final.md`
```

如果后续要继续维护，建议只把 `SKILL-final.md` 当成正式版本，另外两份作为草稿和压缩版保留。

## 维护建议

后续维护这份 skill 时，优先改下面几个地方：

1. **禁用词与高风险表达表**
   - 这是最直接影响 AI 味的部分

2. **四层自检体系**
   - 这是控制成稿稳定性的核心

3. **AI 协作边界**
   - 这是避免“越写越假”的关键

4. **Prompt Template**
   - 这是日常调用最常改的部分

如果只是小修，不建议频繁改动“核心原则”和“模仿指南”，否则风格容易漂。

---

## 最后建议

在真正使用时，不要把这个 skill 当成“自动出稿器”，更适合把它当成：

- 一个风格约束器
- 一个结构整理器
- 一个去 AI 味编辑器
- 一个终稿质检器

这样它的效果会稳定很多。
