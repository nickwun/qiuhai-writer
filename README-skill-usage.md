# 使用说明

本仓库默认主文件是 [SKILL.md](./SKILL.md)。如果你希望在 AI 协作中调用“秋海风格写作”，建议优先引用这一文件，而不是只看首页说明。

## 推荐使用方式

1. 先让模型读取 [SKILL.md](./SKILL.md)。
2. 明确你的写作任务、读者对象、使用场景和长度要求。
3. 指出哪些信息必须保留，哪些内容绝对不能编造。
4. 如果你有原稿，可要求模型按该 skill 做改写、润色或重组。
5. 输出后，对照 `四层自检体系` 做一轮回看。

## 适合怎么用

- 从零起草一篇带有稳定语气的中文文本
- 把已有草稿改写得更克制、更自然、更有留白
- 统一多人协作时的写作风格基线
- 作为个人写作工作流中的固定约束文件

更具体的提示词写法可继续参考 [examples.md](./examples.md)。

## 不建议怎么用

- 要求模型完全冒充真实作者亲历
- 在事实不足时让模型补全具体经历
- 把这个 skill 当作通用营销文案模板
- 不给任何上下文，只要求“写得像一点”

## 最小调用步骤

```markdown
请先阅读 SKILL.md，并按其中要求完成以下写作任务：

- 任务：
- 读者：
- 场景：
- 长度：
- 必须保留的信息：
- 禁止编造的信息：
```

## 结合原稿使用

如果你已有文本，可使用下面的方式：

```markdown
请根据 SKILL.md 改写下面这段文字。
要求：
1. 保留原意，不新增关键事实。
2. 调整语气与节奏，使其更接近秋海风格。
3. 删除明显用力过猛、过度解释或口号化的表达。
4. 改写后再用简短说明指出你删改了什么。
```

## 结合提纲使用

如果你只有一些素材点，可以这样组织：

```markdown
请基于 SKILL.md，把以下素材写成一篇完整中文短文。

素材：
- [场景]
- [关系]
- [一个细节]
- [希望保留的情绪]

要求：
- 不编造未提供的关键经历
- 不写成鸡汤
- 结尾不要强行升华
```

## 建议的协作习惯

- 第一次使用时，先产出一个版本，再要求模型自检修订
- 如果要多版本输出，请要求“角度不同”，不要只换同义词
- 如果任务偏私密，请明确哪些部分只能保持模糊表达
- 如果你发现文本越来越“像模板”，应回到 [SKILL.md](./SKILL.md) 检查是否违反了反向约束
