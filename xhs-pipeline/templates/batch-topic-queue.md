# 批量选题处理队列

用于一次选中多个候选选题时，按顺序记录处理状态。每个选题必须完整完成改写文章、小红书图片和发布文案后，再进入下一个选题。

## 队列

| 2 |  |  |  | 待处理 |  |  |  |
| 3 |  |  |  | 待处理 |  |  |  |

## 状态说明

- `待处理`：尚未开始。
- `改写中`：正在抓取来源、整理笔记、生成 `translated-article.md`。
- `出图中`：正在生成小红书图片和发布文案。
- `已完成`：改写稿、图片、文案和核对均已完成。
- `已暂停`：用户明确要求只生成改写稿，暂不生成图片。
- `失败`：来源不可读取、字幕缺失、图片生成失败或其他阻塞。

## 执行规则

- 按用户给出的选题顺序处理，不要并行交叉生成多个选题的图片。
- 每个选题使用独立的 `xhs-pipeline/workspace/selected/{slug}/` 和 `xhs-pipeline/workspace/packages/{slug}/`。
- 默认连续完成 `translated-article.md`、图片、`xhs-copy.md` 和最终核对。
- 只有用户明确说“只生成改写稿”“先不要生成图片”“先看翻译稿”时，才把状态停在 `已暂停`。
- 如果某个选题失败，记录失败原因；后续选题不依赖它时，可以继续按顺序处理。
