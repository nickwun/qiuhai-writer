# 使用说明

本文件用于说明如何使用 [SKILL.md](./SKILL.md)，以及它与普通写作 skill 的区别。仓库首页 [README.md](./README.md) 只负责介绍仓库；真正用于调用和执行的主文件是 [SKILL.md](./SKILL.md)。

## 这个 skill 是什么

`qiuhai-writer` 是一个中文写作协作 skill，主题是“秋海风格写作”。它不是简单要求模型“写得文艺一点”，也不是给出一些可复制金句，而是提供一套完整的写作约束：

- 规定风格靠什么建立
- 规定哪些边界不能越
- 规定哪些表达应避免
- 规定输出前如何做自检

因此，它更像一个可执行的写作规范文件，而不是一个一次性提示词。

## 什么时候该调用

以下情况适合优先调用这个 skill：

- 你已经有原稿，想在不改掉核心意思的前提下做风格改写
- 你只有零散素材，希望整理成完整、克制、自然的中文文本
- 你想先出提纲，再把提纲写成成稿
- 你在一个长期项目里，希望多次调用时保持稳定语气和边界
- 你需要 AI 帮你写，但又不希望它擅自补人生细节

## 什么时候不该调用

以下情况不建议把它当默认方案：

- 你要的是营销感、销售感、促转化导向的文案
- 你要的是强情绪宣泄、强煽动、强口号式表达
- 你希望模型完全冒充某个真实作者的人生经验
- 你的任务主要是事实说明、知识说明或制度说明
- 你只需要一般润色，不需要明确风格约束

## 它和普通写作 skill 的区别

和普通“写作助手”类 skill 相比，这个 skill 的区别主要在下面几件事：

1. 它先定义边界，再定义风格。
   很多写作提示词只强调语气与文风，这份 skill 先明确不能伪造什么、不能越过哪些事实边界。
2. 它强调风格建立在结构、节奏、视角与细节选择上，而不是建立在口头禅上。
3. 它自带一套四层自检体系，不把“写出来”视为结束，而把“可交付”视为真正完成。
4. 它适合重复调用。
   同一套规则可以长期放进项目里，而不是每次重新写一段零散提示词。

## 推荐工作流

推荐按下面的顺序使用：

1. 先让模型读取 [SKILL.md](./SKILL.md)。
2. 明确当前任务类型。
   是改写现有文章、整理零散素材、先提纲后成稿，还是直接起草。
3. 明确输入边界。
   哪些信息必须保留，哪些内容不能新增，哪些地方只能模糊表达。
4. 让模型先完成一版。
5. 输出前要求模型按 `四层自检体系` 自查。
6. 若需要第二版，优先要求调整结构、节奏、视角和细节密度，而不是只要求“更像一点”。

## AI 与用户的协作边界

调用这个 skill 时，最重要的不是“像不像”，而是“有没有越界”。建议把边界讲清楚：

- 用户负责提供任务、素材、场景和不可编造的信息
- AI 负责组织结构、调整节奏、控制语气、补足表达层次
- AI 不负责替用户虚构关键经历、关系事实和决定性情节
- 当素材不足时，AI 应降低拟真度，而不是擅自补全人生

如果你发现模型开始写出用户没给过的私密经历，这通常说明调用已经偏离了这份 skill 的规则。

## 如何判断一次调用是否成功

一次调用是否成功，不看它“像不像”，而看它是否同时满足下面几件事：

- 文本真正回应了任务，而不是只输出一层气氛
- 风格自然，不像模板，也不像金句拼接
- 没有编造关键事实，没有越界代写真实人生
- 文本已经可读、可交付，不需要靠解释来补救

更具体地，可以直接对照 [SKILL.md](./SKILL.md) 中的“四层自检体系”检查。

## 如何在项目中组织这些文件

推荐按下面的角色分工使用本仓库文件：

- [README.md](./README.md)：仓库首页，用来说明仓库是什么
- [SKILL.md](./SKILL.md)：主文件，默认引用入口
- [README-skill-usage.md](./README-skill-usage.md)：给使用者看的说明书
- [examples.md](./examples.md)：可直接复制的调用示例

如果你把这个仓库作为其他项目的子模块、模板或参考库，默认应把 [SKILL.md](./SKILL.md) 作为第一引用文件。
